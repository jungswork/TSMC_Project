## 1. 核心對象

這本 notebook 處理的核心對象是一張**楠梓測站的逐時長表**：每一列是「某測站、某測項、某個整點」的一筆量測，欄位為 `datetime、site、item、value、flag`。它把環境部原始的「一天一列、24 個小時欄」寬表攤平，之後所有統計都從這張表出發。

輸入是環境部國家空品測站 2021～2025 年的逐時原始檔，輸出是三類東西：

- **指標表**（`data/processed/`）：有效率、年均、百分位、月與日變化、風向頻率，給報告引用。
- **設計輸入表**（`data/processed/`）：把指標翻成 PLAN.md 第 3 節 #1～#4 需要的數字，例如設計用外氣 PM 濃度 Cout、對應的 ISO 16890 濾網等級、AMC 相關氣體濃度、盛行風向。
- **圖**（`report/figures/`）：時間序列、月／日剖面、風玫瑰、污染玫瑰。

## 2. 資料來源與取得方式

### 2.1 為什麼不用 API 抓歷史資料

環境部開放平臺的三個管道都實測過（2026-10-22）：

| 管道 | 實測結果 | 結論 |
|---|---|---|
| `aqx_p_547` 品保後小時值 API | 楠梓只有 2023 年有資料，2018、2021、2022、2024、2025 都是 0 筆 | 只保留最近一個品保年度，拿不到 5 年 |
| `aqx_p_13` 每日更新小時值 API | 2024、2025、2026 年都是 0 筆 | 無法作為歷史來源 |
| 空品監測網「歷史資料下載」頁 | 提供 2018～2025 年「全年逐時資料」，依空品區分檔，連結指向 Google Drive | **採用**：一年一檔，涵蓋完整 |

API 保留的欄位格式仍有用：測站清單 `aqx_p_07` 查到楠梓站的座標與類型，直接寫進 notebook 第一個 cell 當常數，不必連線。

### 2.2 主來源：年度逐時檔（已下載並解壓）

- 頁面：空品監測網 → 歷史資料 → https://airtw.moenv.gov.tw/CHT/Query/His_Data.aspx ，年份 2021～2025，資料型態「全年逐時資料」，空品區「高屏空品區」。
- 放置：`data/raw/airtw/<年份>/<站名>_<年份>.csv`，原始 zip 留在 `data/raw/`。整個 `data/raw/` 不進版控。
- **檔案格式（解壓後檢視）**：每年一個 zip，內含高屏空品區 15 站各一個 CSV（含楠梓、橋頭、仁武、左營）。CSV 為 UTF-8 帶 BOM，表頭 `測站,日期,測項,00,01,…,23,`，每列結尾多一個空欄；日期格式 `2023/01/01 00:00:00`；楠梓每年 365（閏年 366）天 × 18 測項，無缺列。無效值不是數值後綴，而是整格換成標記：`#`（儀器檢核無效或超出偵測極限）、`*`（程式檢核無效）、`x`（人工檢核無效）、`A`（儀器檢核）、`NA`（缺值）；楠梓五年合計約 1～3％ 的格子帶標記。

## 3. Notebook 內的資料流與章節

```
data/raw/airtw/<年>/<站>_<年>.csv
        │  第 2 節：載入與清理（函式 load_year、to_long）
        ▼
長表 hourly_long（datetime, site, item, value, flag）──→ data/processed/01_aq_hourly_long.csv
        │  第 3～5 節：指標計算（函式 coverage、annual_stats、
        │              monthly_profile、diurnal_profile、wind_rose、pollution_rose）
        ▼
指標表 ──→ data/processed/01_aq_*.csv，圖 ──→ report/figures/01_*.png
        │  第 6 節：翻成設計輸入（函式 design_cout、design_iso16890、design_amc、design_wind）
        ▼
設計輸入表 ──→ data/processed/01_design_*.csv
```

每個章節的函式只吃長表（或上一節的小表）、回傳一張表，cell 之間不靠隱藏的全域狀態傳遞，這樣你逐 cell 看時每個 cell 的輸入輸出都明確。

### 3.1 第 2 節：載入與清理

- **做什麼**：讀楠梓五年 CSV，攤平成長表；把整格標記（`#`、`*`、`x`、`A`、`NA`）拆成 `value`（數值，無效為 NaN）與 `flag`（原始標記，有效值為空字串）兩欄。
- **為什麼保留 flag 而不是直接丟掉**：無效小時的比例本身是資訊（某測項某年有效率太低，統計就不能用），留著 flag 才能在第 3 節算有效率；丟掉就查不回來。
- **為什麼用長表**：後面所有統計都是「依測項、依時間分組」，長表一個 `groupby` 就能做；寬表每加一個測項就要多一欄處理。需要跨測項對照（例如 PM2.5 對風向）時再臨時 pivot。
- **輸出格式用 CSV 不用 parquet**：parquet 要多裝 pyarrow，5 年 × 18 測項 × 8760 小時約 79 萬列，CSV 約 30 MB，pandas 讀取幾秒內，不值得多一個依賴。

### 3.2 第 3～5 節：指標計算

每個函式吃長表、回傳一張小表，彼此獨立：

| 函式 | 輸出 | 說明 |
|---|---|---|
| `coverage` | 測項 × 年的有效小時比例 | 低於門檻（暫定 75％，依環境部年報慣例）的年份在後續統計中標示 |
| `annual_stats` | 測項 × 年：均值、中位、P95、P99、最大值 | 設計用濃度通常取 P95 或 P99，不取平均，因為濾網要撐過高濃度時段 |
| `monthly_profile`、`diurnal_profile` | 測項 × 月、測項 × 小時 | 看季節（冬季 PM 高、夏季 O3 高）與日夜差，決定 MAU 進氣控制是否需要分時段 |
| `wind_rose` | 16 方位 × 風速級的頻率 | 盛行風向；靜風（風速 < 0.5 m/s）另計 |
| `pollution_rose` | 16 方位 × 測項的平均濃度 | 哪個方向吹來時 PM 或 SO2 高，對應周邊污染源方位 |

### 3.3 第 6 節：翻成設計輸入

- **Cout（#1）**：CR p43 的公式要的是「每立方公尺 ≥ 0.5 µm 粒子數」，但測站只有質量濃度，兩者之間沒有可靠的換算依據（需要粒徑分布與粒子密度，測站都沒有量）。做法：只給 PM10 與 PM2.5 的質量濃度（P95，另列平均、P99、最大值），不做質量→粒子數換算；公式需要的粒子數由設計組另行取得（濾網廠商外氣計數資料或現場粒子計數器量測）。2026-10-22 原本的對數常態假設換算因缺乏依據已移除。
- **ISO 16890 等級（#2）**：ISO 16890 用 ePM1、ePM2.5、ePM10 的捕集效率分級。給定 MAU 出口目標濃度（例如 PM2.5 ≤ 1 µg/m³，由設計組定），所需效率 = 1 − 目標 ÷ Cout，再對照等級表。輸出「目標濃度 → 所需效率 → 建議等級」的小表，目標濃度留幾個情境。
- **AMC（#3）**：SO2、NO2、O3、NMHC 的年均與 P95，單位由 ppb 換成 µg/m³（AMC 濾網規格常用），對照 ISO 14644-8 的 AMC 等級表示法。NH3 與 H2S 無資料，表中明確留空並註明。
- **風向（#3、#4）**：盛行風向、海風方向（楠梓在海岸東側，西南風為海風）的出現頻率、各方向的 PM 與 SO2 平均濃度。給 MAU 進氣口方位與鹽霧濾網需求的判斷用。

`notebooks/01_Air_Quality_Nanzih.ipynb`，每節一個目的，每節結尾把結果寫到 `data/processed/`：

5. **風玫瑰與污染玫瑰**：圖加表。
6. **設計輸入表**：四張表，附假設說明。
7. **小結**：三到五句，哪些數字會進報告、哪些有缺口。

## 5. 關鍵取捨

- **年度檔 vs API**：API 只有 2023 年，年度檔有完整 5 年；代價是要手動下載。選年度檔，因為沒有 5 年資料就做不出季節與年際變化。
- **設計濃度取 P95 而非平均或最大值**：平均會低估高污染時段，最大值常是沙塵或異常事件，P95 代表「一年中 438 小時會超過」的水準，是濾網選型常用的保守值。報告中三個數字都列，由設計組決定。
- **不做質量→粒子數換算**：換算要假設粒徑分布與密度，測站都沒有量，結果缺乏依據；只用質量濃度與 ISO 16890，粒子數留給設計組另行取得。
- **全部寫在 notebook 內**：之後南科、中科會有三本幾乎一樣的 notebook，中途改統計邏輯要改三處；以期末專案的規模，這比維護模組便宜。
- **先只做楠梓**：站名與路徑參數化，之後只換第 1 節設定與原始檔。
